# 量子回路教材：初学者視点の模擬レビュー記録

対象：`quarto/qiskit/algorithms.qmd` と、その授業パーシャル。2026年10月18日実施。

量子力学を学んだ直後で量子回路は初めて読む学生を想定し、二つのAIレビュー役に依頼した。実在の学生からの受講報告ではない。目標は、回路の各位置の状態を手計算し、欲しい出力から部品を選べる教材にすること。

- 担当A：用語と式変形を追い、別の入力にも計算法を適用できるかを確認。
- 担当B：生成済み図8枚と本文を読み、回路図・途中状態・設計意図の接続を確認。

## 第1回：指摘と修正

各担当から4件、重複を除くと6箇所の指摘があった。

| つまずき | 修正 | 対象 |
| :--- | :--- | :--- |
| エンタングルした状態の片側へのHを追えない | 各項への作用と、下の文字が同じ振幅を組にする規則を追加 | `_03-two-qubits.qmd`、`_06-design-deutsch.qmd` |

`quarto/templates/quantum_textbook_template.qmd`、`theory_template.qmd`、`quarto_feature_showcase.qmd`、`docs/features.md` を参照。常時表示する計算規則・設計意図、練習、折りたたむ解答・任意の補足を区別し、比較する内容にはレスポンシブなgridを使用した。

この段階でも、初学者向け補足と設計・レイアウトの二つの模擬レビューを行い、次の6提案を採用した。

- Hの二つの出力は、更新前の同じ二つの入力から計算することを明記。
- 正規化を誤計算の修復ではなく検算に使う補足を追加。

## 日本語の推敲と、説明順序の再レビュー

ユーザーから「振幅を確率に置き換えてはいけない、という説明では理由が分からない」と指摘を受けた。用語の定義、計算、結果の説明が、前から読むだけでつながるかを改めて確認した。

- [refine-ja](https://github.com/finelagusaz/ja-writing-tools/blob/main/plugins/refine-ja/skills/refine-ja/SKILL.md)：SKILL.md、共通ルール、技術文書モードを読んで使用。意味の保持、指示語の明確化、用語の統一、冗長な表現の削減を採用した。
- [yomiyasu](https://github.com/nanaism/yomiyasu/blob/main/skills/yomiyasu/SKILL.md)：基本原則などを参照。主張・条件・否定・言い切りの強さを保つ方針を確認した。付属のlintや検査ハーネスは実行していない。
- [humanizer-ja](https://github.com/matsutouya/humanizer-ja/blob/main/SKILL.md)：適用範囲と文・語彙の改善例を参照。一人称や感情を加える方法は、この教材には採用していない。

どのスキルもインストールせず、公開ファイルを読んで参考にした。「AIっぽい単語」の一括置換は行わず、数式の意味と読者の理解を優先した。

### 修正した読解上の障害

ユーザーの指摘に加え、二つの模擬レビュー担当から7件の指摘があった。

| つまずき | 修正 |
| :--- | :--- |
| 振幅と確率の違いを説明する前に禁止を述べる | Born則で二乗の意味を示し、Hを学んだ後に符号の違いが出力を変える例を確認する |
| 「二成分」が状態の成分と計算途中の項のどちらか分からない | 同じ出力の係数になる二項を具体的に示し、先に二乗した場合の誤答とも比較する |
| 「上の文字」と、ケットの左右の対応が分からない | 上の線は量子ビットa、ケットでは左の文字と明記する |
| 未説明の「混合」を、目標状態を指定する理由に使う | 同じ測定確率になるプラス符号とマイナス符号の状態で説明する |
| 「重ね合わせの成分は振幅を足す」が、異なる基底の係数まで足す指示に読める | 同じ基底状態の係数をまとめる場合に限定する |
| 密度行列のトレースが測定確率になる理由がない | 外積の左上がBorn則の確率であり、その準備平均が密度行列の左上になることを示す |
| 初出の一般式を「以前出てきた」と呼ぶ | Hの具体例から一般のUへ広げ、測定結果yと射影を定義する |
| Kraus表現の一般式が目的より先に出る | 確率的にZを掛ける例から始め、左右の係数の積が確率になることを示す |

このほか、「状態に付いていた係数を残したまま、行き先を入れ替える」などの曖昧な言い回しを、どの基底の係数がどこへ移るかを示す文に改めた。

再レビューでは、補講の4件は解消し、新しい指摘はなかった。冒頭には「符号を残す理由を次節に預けている」という1件が残ったため、正負の振幅を二乗すると区別が失われることを、その場で説明する形に修正した。Hの例は、後から理由を補うためでなく、符号の違いが実際に測定結果を変えることを計算で確かめるために残した。

ユーザーがTailscale経由で閲覧しているため、配信は確認済みHTMLのコピーに固定し、編集・レンダリングとは分けた。修正中のHTMLは逐次公開せず、検証後に配信先をまとめて切り替える。

最後の1件も再確認で解消と判断された。`just check` は通過し、最後の段落修正後にも構造検証と全14セルを実行するHTMLレンダリングが通過した。Pythonコード14セル、既存アンカー、PDFリンクは変更していない。ブラウザでは画像8枚、数式のエラーがないこと、幅1440pxと390pxで本文が画面幅に収まること、Kraus表現の補足を開けることを確認した。
